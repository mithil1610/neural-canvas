# Release 1.3.0 Manual QA Test Plan & Verification Checklist

**App**: Axiom – Your AI Second Brain  
**Version**: 1.3.0 (Build 2)  
**Target Platform**: iOS 16.0+  
**Test Environment**: Physical iPhone or iOS Simulator with Firebase Emulators or Staging Firebase Project

---

## Pre-Requisites & Test Accounts Setup

1. **Test Accounts**:
   * **User A (Free Tier)**: Newly registered account with 0 uploads.
   * **User B (Creation Engine Tier)**: Account with active RevenueCat `creation_engine` entitlement.
   * **User C (Infinite Brain Tier)**: Account with active RevenueCat `infinite_brain` entitlement.
2. **Tools**:
   * Xcode / Console app for viewing device logs.
   * Firebase Emulator Suite or Firebase Console (Firestore, Storage, Authentication, Functions).
   * RevenueCat Dashboard Sandbox environment.

---

## Test Suite

### 1. Authentication & Security
- [ ] **1.1 Fresh Email Registration**:
  - Register with a new email address.
  - Verify user document is created at `/users/{uid}` with default `accountTier: "Free"`.
  - Verify client cannot write to `accountTier` or `dailyUploadCount` directly (verify rules block client edits).
- [ ] **1.2 Sign In & RevenueCat Binding**:
  - Sign in with User A.
  - Check device log: verify `Purchases.logIn(uid)` is called and RevenueCat App User ID matches Firebase Auth UID.
- [ ] **1.3 Biometrics / Passcode**:
  - If Face ID / Touch ID is enabled, test biometric unlock on app resume.
  - Test fallback to device passcode.
- [ ] **1.4 Sign Out**:
  - Tap sign out in profile.
  - Verify `Purchases.logOut()` is invoked.
  - Verify user is navigated to `AuthGate`.
- [ ] **1.5 Cross-User Isolation (Security Rule Check)**:
  - Sign in as User A. Attempt to access or query documents from User B (`/users/{uid_B}/knowledge_base`).
  - Verify Firestore rules return `PERMISSION_DENIED`.

---

### 2. The 5 Capture Modalities
- [ ] **2.1 Modality 1: Document Camera Scan**:
  - Tap `+` -> Camera / Scan.
  - Capture a document page and confirm upload.
  - Verify file is saved in Cloud Storage at `users/{uid}/uploads/<timestamp>_photo.jpg`.
  - Verify server-side `analyzeAsset` runs, generates summary & tags, and creates an entry in `users/{uid}/knowledge_base/`.
  - Verify source file in Storage is **NOT** deleted after analysis.
- [ ] **2.2 Modality 2: Voice Note Recording**:
  - Tap `+` -> Audio / Mic. Record 10 seconds of speech (e.g. "Meeting with Sarah next Tuesday at 3pm to review the Q3 budget").
  - Complete recording and upload.
  - Verify audio file is saved at `users/{uid}/uploads/<timestamp>_voice_memo.m4a`.
  - Verify Cloud Function transcribes and summarizes the voice memo into the vault.
- [ ] **2.3 Modality 3: Photo Library Import**:
  - Tap `+` -> Photo Library. Select an image containing text or a diagram.
  - Verify image uploads to `users/{uid}/uploads/` and appears in Neural Canvas / Recent Vault items.
- [ ] **2.4 Modality 4: Document File Import (PDF / Word)**:
  - Tap `+` -> Document. Select a `.pdf` or `.docx` file from the iOS Files picker.
  - Verify upload succeeds (content type permitted by `storage.rules`).
  - Select an invalid file type (e.g. `.exe` or `.zip`); verify `storage.rules` rejects the upload with permission denied.
- [ ] **2.5 Modality 5: Quick Paste Text**:
  - Tap `+` -> Paste / Quick Note. Paste clipboard text.
  - Verify text note is indexed directly in Firestore `knowledge_base` with embedding generated by `getEmbedding` Cloud Function.

---

### 3. iOS Share Extension
- [ ] **3.1 Share URL / Text from Safari**:
  - Open Safari, navigate to an article, tap iOS Share Sheet -> Axiom.
  - Tap Save.
  - Open Axiom; verify the shared article appears in the processing queue and is filed into the Vault.
- [ ] **3.2 Share Photo from iOS Photos**:
  - Select a photo in Apple Photos app, tap Share -> Axiom.
  - Open Axiom; verify the photo is uploaded and auto-indexed.

---

### 4. Chronos Matrix Event Extraction & Timezone Verification
- [ ] **4.1 Specific Local Time**:
  - Upload a note or voice memo stating: *"Team sync on October 15th at 2:30 PM"*.
  - Verify Cloud Function `extractEvents` receives the device's IANA timezone (e.g. `America/New_York` or `Europe/London`) and current local date.
  - Verify model response contains ISO-8601 string with explicit offset (e.g. `2026-10-15T14:30:00-04:00`), **NOT** UTC `Z`.
  - Verify reminder notification is scheduled for 30 minutes before (2:00 PM local time).
- [ ] **4.2 Relative Date ("Next Friday")**:
  - Note: *"Dinner party next Friday at 7pm"*.
  - Verify relative date resolves against the user's current local date.
- [ ] **4.3 Date-Only Event (9:00 AM Default)**:
  - Note: *"Dad's birthday on November 3rd"*.
  - Verify the event has no time specified.
  - Verify client schedules the reminder for **9:00 AM local time** on that date.
- [ ] **4.4 Past Events Filter**:
  - Note with a date in the past (e.g. yesterday).
  - Verify `EventTimeParser.filterPastEvents()` discards the past event and does not schedule a dead notification.

---

### 5. Chat & Server-Side RAG
- [ ] **5.1 Vault Query**:
  - Open Chat tab. Ask a question about an asset uploaded in Step 2 (e.g. *"What did Sarah and I discuss about the budget?"*).
  - Verify `chatWithRag` Cloud Function retrieves only the relevant top 15 items (capped at 6,000 characters).
  - Verify the AI response accurately references the specific knowledge base item.
- [ ] **5.2 Auto Session Titling**:
  - Send the first message in a new chat.
  - Verify `updateChatTitle` Cloud Function triggers and names the session appropriately in the chat drawer.
- [ ] **5.3 Stream / Network Recovery**:
  - Simulate network drop during chat; verify appropriate error state is shown and user can retry.

---

### 6. Subscriptions, Paywall & Entitlement Sync
- [ ] **6.1 Paywall Display & Offerings**:
  - Open Paywall sheet (`PaywallSheet`).
  - Verify prices are loaded dynamically from StoreKit / RevenueCat (e.g. "$4.99/mo", "$49.99/yr"). No hardcoded prices.
  - If an introductory offer or free trial is configured in App Store Connect / RevenueCat, verify the "Free Trial" or "Intro Offer" badge is visible on the package card.
- [ ] **6.2 Purchase Flow**:
  - In StoreKit Sandbox, purchase the "Creation Engine" monthly tier.
  - Verify purchase completes successfully.
  - Verify `syncEntitlements` callable is invoked immediately.
  - Verify user document in Firestore updates `accountTier` to `"Creation Engine"`.
  - Verify UI unlocks Creation Engine features immediately without app restart.
- [ ] **6.3 Webhook Verification**:
  - Trigger a renewal or cancellation event in RevenueCat sandbox webhook simulator.
  - Inspect Cloud Functions log for `revenuecatWebhook`: verify secret is authenticated and Firestore `accountTier` is updated.
- [ ] **6.4 Restore Purchases**:
  - Sign in on a second test device or reinstall app.
  - Open Paywall -> tap "Restore Purchases".
  - Verify StoreKit restores receipts, `syncEntitlements` runs, and tier is applied.

---

### 7. Quota Enforcement
- [ ] **7.1 Free Tier Daily Upload Cap (10 uploads/day)**:
  - Sign in with User A (Free Tier).
  - Perform 10 uploads. Verify `dailyUploadCount` reaches 10.
  - Attempt the 11th upload.
  - Verify Cloud Function transaction returns `RESOURCE_EXHAUSTED` with message: *"Daily upload limit of 10 reached for your tier."*
  - Verify client displays the upgrade paywall prompt.
- [ ] **7.2 Daily Reset**:
  - Advance Firestore `lastUploadDate` to yesterday.
  - Attempt upload. Verify counter resets to 1 and upload succeeds.
- [ ] **7.3 Infinite Brain Unlimited**:
  - Sign in with User C (Infinite Brain).
  - Perform >15 uploads; verify all succeed without quota blocks.

---

### 8. Growth & In-App Review Prompts
- [ ] **8.1 Third Auto-Filed Milestone**:
  - Fresh install with clean `shared_preferences`.
  - Upload 1st and 2nd item: verify `in_app_review` is NOT requested.
  - Upload 3rd item: verify `ReviewService.checkAndRequestReview()` triggers Apple's `SKStoreReviewController`.
- [ ] **8.2 First Reminder Milestone**:
  - Fresh install. Create the first event reminder.
  - Verify review prompt triggers upon successful reminder creation.
- [ ] **8.3 90-Day Cooldown**:
  - Trigger review once. Trigger a 4th upload or 2nd event immediately.
  - Verify review prompt is suppressed by the 90-day cooldown check.
- [ ] **8.4 First Launch Suppression**:
  - Launch app for the first time; verify review dialog is never presented on launch.

---

### 9. Account Deletion ("Automated Purge Vault")
- [ ] **9.1 Purge Confirmation Dialog**:
  - Navigate to Profile -> "Delete Account" / "Purge Vault".
  - Verify scary confirmation dialog appears requiring explicit user confirmation.
- [ ] **9.2 Server-Side Execution**:
  - Confirm deletion.
  - Verify Cloud Function `deleteAccount` executes:
    - Recursively deletes Cloud Storage files under `users/{uid}/`.
    - Recursively deletes Firestore collections: `knowledge_base`, `chats`, `upcoming_events`, `usage`.
    - Deletes Firestore document `/users/{uid}`.
    - Deletes Firebase Auth user record.
- [ ] **9.3 Client Post-Purge Cleanliness**:
  - Verify all scheduled local notifications are cancelled (`cancelAll()`).
  - Verify RevenueCat logs out (`Purchases.logOut()`).
  - Verify client navigates back to `AuthGate` in clean logged-out state.
  - Attempt to sign back in with deleted credentials; verify Firebase Auth returns `user-not-found`.
